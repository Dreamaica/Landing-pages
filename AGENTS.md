# Agent Operating Standard

These instructions apply to every automated or agent-assisted change in this repository.

## Protect the real asset

The value here is not a generic landing-page template. It is the distinct voice, cultural context, relationships, offers, and original project architecture behind each initiative.

- Preserve named people, places, history, symbols, and project-specific language unless the owner asks for a change.
- Do not flatten culturally specific material into generic wellness, tourism, technology, or startup copy.
- Do not invent partners, endorsements, statistics, legal claims, prices, events, or product availability.
- Keep unreleased strategy, credentials, customer information, and private operating data out of this public repository.

## Human ideas first

Use the owner’s actual points, vocabulary, and intent as the source material. The agent may organize, tighten, test, and clarify. It must not replace substance with symmetrical slogans, inflated claims, filler, or a uniform “AI voice.”

Public copy should be concrete, believable, and easy to read aloud. If a factual claim cannot be verified, qualify it or remove it.

## Small workflow first

For new tools or automation:

1. define one narrow workflow with a clear input and useful output;
2. test it with representative material;
3. record what worked, failed, cost money, or required manual judgment;
4. then decide whether it remains private leverage or becomes a product.

Do not install a skill, plugin, dependency, or MCP server merely because it is popular. Review its source, permissions, data flow, maintenance, license, and supply-chain risk first.

## Engineering rules

- Inspect the current page structure before editing.
- Preserve working routes, anchors, embeds, and deployment assumptions.
- Keep secrets and privileged model calls on the server.
- Prefer small, reversible commits with descriptive messages.
- Run the production build after code changes.
- Check responsive behavior, keyboard access, visible focus, readable contrast, and empty/error states.
- Do not merge placeholders, dead controls, fabricated data, or silent failure paths into a public experience.
